Building production-grade AI applications

A demo that works once is easy. An AI application colleagues rely on every day is engineering. This is how I take agentic AI from a curiosity experiment to a production application at the office.

Agent orchestration

LangGraph state machines with checkpoints, retries, branching and human-approval steps, so multi-step agents stay predictable.

Grounded answers

RAG over internal documents with tuned chunking and retrieval, and answers that cite their sources instead of guessing.

Observability & evals

LangSmith tracing on every run, plus evaluation datasets to catch regressions before a prompt or model change ships.

Tool integrations

MCP servers that connect agents to internal systems and APIs through clean, permissioned interfaces.

Guardrails & reliability

Structured outputs, input validation, fallbacks and timeouts, so failures are handled, not surfaced to users.

APIs & deployment

FastAPI services, containerised and shipped through CI/CD, with token-cost and latency budgets in mind.

Kestrel: a production-grade B2B buying agent

A prototype buying assistant for a fictional B2B distributor, built to push the production practices I use at work further: the agent proposes carts and quotes, the buyer stays in control.

  • LangGraph agent with an intent router and least-privilege tools
  • Prices and business rules in deterministic code: the LLM never calculates a price
  • Human-in-the-loop: the agent proposes carts and quotes, the buyer confirms
  • Fallbacks for LLM and ERP outages, testable live in the UI
  • Hybrid search (dense + BM25) with reranking
  • Eval harness: LLM judge, deterministic checks and quality gates

What the evals taught me

  1. Evals only catch what you think to test. Tests passed while the agent happily wrote poems: nothing covered off-topic requests.
  2. Single-question tests hide multi-turn bugs. Adding multi-turn cases took that scenario from 25% to 100%.
  3. Sometimes the eval is wrong. One "failure" was a check contradicting its own expected answer.
  4. Not every safeguard earns its cost. The intent router added 1.5 s with no measurable accuracy gain, so it stays for containment, marked to optimise.
  5. Good design beats guardrails. Prices only come from code, so the price guard never fired once.

Measure before you believe.
